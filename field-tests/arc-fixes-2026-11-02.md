## Item 39: Chromium resource reader

New target-free `inspect_chromium_resources` /
`rea inspect-chromium-resources` validates an unwrapped DataPack v4/v5 index,
pages original numeric IDs/direct aliases, preserves table/payload ranges and
stored hashes, and reads complete bounded selected content. Gzip and Chromium-
envelope Brotli decode only the selected resource. `decode:false` / CLI
`--stored` retains the original payload. Decoded bytes have their own SHA-256 and
complete hex; an optional strict text preview does not replace those bytes.

The reader checks metadata/payload overlap, ordering, uniqueness, table/sentinel
bounds and alias indices before paging. Empty resources and ID zero are valid.
Nonzero padding, the positional sentinel's raw ID and unclaimed ranges remain
visible. Alias payload hashes are cached by canonical index, preventing repeated
large hashing for aliases. Stored/decoded budgets are checked before expensive
expansion; native codecs enforce output bounds. Brotli length mismatches and
trailing compressed input are refused.

Public owned-byte journeys cover v4/v5 and aliases, UTF16/binary coexistence,
gzip/Brotli round trips, stored-content CLI/MCP parity, malformed indexes,
compression/size failures, strict SDK rejection and recovery. Successful replies
validate actual advertised JSON Schemas and canonical contracts, with exact
text/structured agreement. SDK input-validation text is distinguished from
canonical JSON handler errors.

## Item 40: guarded receiver identity

The owning lexical API-reference model now recognizes the narrow URL/
URLSearchParams initialization with one sole try-body assignment, an immediately
preceding uninitialized single `let`, no finally, and an abrupt return/throw
catch. A receiver fact is valid only at a later same-frame read. Guard metadata
survives immutable aliases and is checked per use, avoiding unconditional
binding-cache promotion. Potential identities are separately available to the
visible-write collector, so closure/member/prototype mutations invalidate facts
even when their own reads cannot be proven safe.

Eleven public source scenarios pin positive constructors/aliases, same-binding
before/after reads, callable/class boundaries, closure writes, catches/finally,
conditional initialization, reassignment, preinitialized bindings and shadowed
constructors. Unknown custom HTTP clients stay low-confidence candidates; known
fetch remains recognized. Existing endpoint-payload and chained-receiver public
regressions pass too.

Arc's unchanged three-script scope now has **zero endpoint candidates**; its
former query key `v` is not promoted to a network candidate. The retained mutable
fixture still has the exact recognized fetch control
