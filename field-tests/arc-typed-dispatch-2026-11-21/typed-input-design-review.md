A new producer must parse the **complete function type**, including its exact parameter/result structure and annotations, before lowering it to a native thick closure with one enum argument. The minimum needed for the input-domain question is narrower than proving all 23 captures or ARC lifetime behaviour: prove that the **relevant code word at the selected typed field** came from this construction, and that the actual selected closure invocation has that field's type. Track the context as belonging to the same value, or preserve an explicit opaque-valid-context premise. ## The argument and dispatch proof

For the selected code `0x100d92ebc`, the full adapter is `LDR X1,[X20,#0x10]; B 0x100d910dc`. It does not overwrite `X0`. The reader's pre-call instructions save `X1` into `X19` and call `0x1005aa5e4` at `0x100d910f0`, leaving `X0` unchanged. Under the admitted native Swift closure ABI, an exactly typed one-argument pure-enum closure therefore carries the enum representation to this **invocation** of the helper. Do not infer a helper-global formal parameter type.

The helper copies incoming `X0` into `X8`, masks it with `0xffff`, loads unsigned `LDRH` from `0x1036db410 + (X8 << 1)`, and branches to `0x1005aa61c + (halfword << 2)` at `0x1005aa618`. The mask admits 65,536 representations. Only the selected valid-enum context can restrict them to `[0,297)`.

After that domain is established, decode exactly `2 * 297` bytes and validate the instruction form, nonwrapping arithmetic, source initialization/immutability, aligned executable destinations and source-boundary ownership. Reject unknown transformations, mismatched register widths, clobbers, foreign/bypass entries, disagreeing joins and unresolved computed forwarding. Reflection names can label that enum's ordinal tags; they do not identify another same-name/count enum or establish all source-level callers.

## Why the current repair carrier cannot be reused unchanged

`ReaGhidraSwiftEnumSwitches.Recovery` is owner-wide. `repair()` installs unconditional computed edges, disassembles destinations, extends the owning function and writes a `JumpTable` override. `tables()` and the public jump-table schema have no typed invocation context/domain field. Adding a limitation string cannot make those mutations conditional. One typed caller is therefore insufficient for this repair path.

The newly owned `TypedClientControls` fixture is a decisive case: optimized typed, `UInt16` unsafe-cast and same-name/different-owner sources share constructor/thunk/reader/switch implementation code while retaining distinct field types. The raw-input field does not supply a valid-enum input premise, and the other enum's identity cannot be replaced by the primary enum just because code or case counts agree. An incomplete caller inventory cannot establish the absence of those paths in Arc.

A minimal new observation contract should carry an artifact-bound `context_id`; exact typed root operation and buffer identity; Client/field/function-type identities; code/context origins; ordered argument-flow anchors; selected enum descriptor and `[0,N)` domain; dispatch/table/anchor/scales; context-scoped mappings; named assumptions; unknown contexts and explicit missing facts. Set `program_mutations = false`. Emit `proved` only for the complete declared conditional chain, otherwise `partial` with the missing owner/origin/type fact. Do not populate a helper-global parameter type, owner-wide jump-table override, empty default list interpreted as exhaustive for all callers, or ordinary inferred CFG edges. A future global repair would need an independently closed all-entry domain proof or context specialization, neither supplied by this review.

The existing concrete `emulate_function` facility is different: it accepts exact caller-selected register/memory values and returns controlled-replay Evidence for that bounded run. It can check a selected helper input without proving the enum domain. A finite set of successful concrete runs does not prove closure typing, exhaustiveness for unexamined inputs or active dependency injection. No emulator was run by this review.

## Reuse and decisive controls

Reuse the signed-relative/fixup identity reader and associated-type data decoder for exact nominal identities, with their unknown states preserved. Reuse bounded CFG/reaching-definition helpers for local argument flow and known foreign-entry rejection. The existing enum layout reader currently requires a payload case; add a separate strict pure-enum layout/representation reader rather than weakening the older lanes. The expanded Swift demangler tree classifier shows how to distinguish the declaration's own function type from a callback/return type, but it does not currently parse this symbolic closure field or lower its ABI. None of these components currently proves cross-function constructor output ownership or typed closure dispatch.

Qualify the new context carrier against the merged typed/UInt16/foreign-owner fixture first. Additional independent negatives should include: associated `Value` with unrelated getter signature; shared VWT helper under different metadata; a same-layout untyped constructor; wrong field offset; enum appearing only in return type; malformed/trailing/generic or unsupported ABI manglings; changed/mixed closure pair or a later rewrite; hidden `X8` result escape; `X0` clobber or forwarding bypass; and unsigned-halfword/scale/anchor/target violations. The JSON lists their expected outcomes and exact source anchors.

No full-Arc, durable preferences, active UserDefaults instance, account/sync or runtime dependency-selection claim follows. No production recovery change is proposed until the typed root/origin and conditional representation are both concrete.
