# Bounded ARM64 halfword-dispatch fixture and recovery design

Two owned Swift fixtures reproduce the unguarded halfword dispatch. They were compiled and inspected statically; neither library was loaded or executed, and no REA+/Ghidra provider was launched. All new work is confined to this directory. This establishes a source-owned compiler example, not a fixed REA+ capability.

`Setting297.swift` declares 297 empty cases with distinct String raw values. Apple Swift 6.3.3, `-O -whole-module-optimization`, arm64 macOS 14, emits the synthesized getter at `0x8b4`. It masks X0 with `0xffff`, materializes table `0x3270`, materializes anchor `0x8dc`, loads an unsigned halfword indexed by two, scales that halfword by four, and branches. There is no local bounds guard. The original nominal descriptor is `0x67dc`: flags `0x52`, zero payload cases and 297 empty cases. Its field descriptor independently has 297 records. The 594-byte table has 297 distinct aligned targets in the getter's symbol interval.

`ManualSetting297.swift` declares the same number of empty cases and an explicit `preferencesKey` switch. It has no RawRepresentable conformance. Its getter at `0x868` uses table `0x19a0` and anchor `0x890`; the 594 table bytes are identical to the raw-value getter's table. This control shows that the instruction/table shape cannot identify a protocol requirement or prove an enum parameter type. The mask admits 65,536 integer representations; it does not prove the 297-case bound.

`fixture-observation.json` records both binary digests, linked instructions, original descriptor fields, all table entries/targets and the exact imported witness bindings. `verify_fixture.py` rechecks those static facts without opening a provider. The dylibs and module cache remain local and are ignored; source, assembly, disassembly and receipts are reviewable text.

The owned RawRepresentable fixture offers one conservative future identity route. Its original conformance descriptor at `0x352c` has three resilient requirement/implementation pairs. Exact imported requirements, rather than positions guessed from a witness table, identify:

- `_$s8RawValueSYTl`, the associated-type descriptor, whose implementation is tagged symbolic type data for `SS` (String), not executable code.
- `_$sSY8rawValuexSg03RawB0Qz_tcfCTq`, the raw-value initializer requirement.
- `_$sSY8rawValue03RawB0QzvgTq`, the raw-value getter requirement, whose implementation is witness `0x1808`.

The getter witness loads `LDRH W0,[X20]` from formal Self, directly calls `0x8b4`, and writes the result through the indirect output pointer. The imported requirements resolve through exact libswiftCore binding slots, retained in `fixups.txt`; `demangled-requirements.txt` records the local demangler's interpretation. Formal typed Self supplies the input identity, the witness supplies the two-byte load and argument forwarding, and the selected pure-enum descriptor supplies the finite tag domain. The associated RawValue type is a separate return-type constraint; it must not be mistaken for the input Self type. No runtime witness table was instantiated.

A production lane based on that chain should reject unresolved/ambiguous owner descriptors, unknown requirement identities, generic substitutions it cannot bind, payload/resilient enum layouts it does not support, wrong argument widths/registers, intervening clobbers or transformations, unknown indirect forwarding and table/address arithmetic failures. External protocol flags and runtime ordering can remain unavailable even when a resilient pair names an imported requirement exactly. The producer must retain the external ABI/signature premise and source binding; a familiar spelling or a presumed slot number is insufficient.

Only after input identity and finite domain are proved should the producer read exactly `2 * caseCount` bytes. It should verify the exact unsigned LDRH, address scale one, target scale two, decoded anchor/base, initialized source-bound bytes, nonwrapping arithmetic, executable aligned targets and a closed dispatch window. It should distinguish ordinal mappings from source case names and preserve the validity premise: the formal input is a valid value of that selected Swift enum under the admitted ABI. A typed witness route gives a conditional path proof; it does not establish every possible untyped caller of a helper. A separate locally guarded integer-table lane can derive its bound from a proved dominating unsigned comparison and needs no enum identity.

For Arc, the method at `0x1005aa5e4` remains an anonymous Setting-to-key dispatcher, not an established RawRepresentable getter. The selected conformance scan's zero matches, with 401 unresolved index identities, does not establish global absence. The owned RawRepresentable route cannot be substituted for missing Arc identity evidence.

The root investigator's selected default-client path offers another plausible future route: resolve field zero `boolForSetting`'s exact closure type to the Setting descriptor; prove the UserDefaultsClient layout and constructor return; bind the code/context pair stored at the typed field; then follow the thick-closure ABI and preserve the Setting argument through adapter and reader into the dispatcher. Public instruction records independently show constructor `0x100d92a28` stores code `0x100d92ebc` and its context at output offset zero (`0x100d92cd0..0x100d92cdc`); adapter `0x100d92ebc` loads only X1 from context and branches to `0x100d910dc`; the reader preserves X0 before calling `0x1005aa5e4` at `0x100d910f0`. These corroborate the forwarding portion. Metadata-to-field/type/layout binding, construction ownership, closure calling convention and the full selected-path proof still need producer implementation and adversarial qualification. The default initializer's presence does not prove active runtime dependency injection.

This route must stay conditional on that selected default path and valid typed closure input. It must not label all invocations of the anonymous dispatcher as typed, infer durability from dispatch, or guess count from nearby data. No production change was made.

Useful later counterexamples are: an identical UInt16 dispatch beside an unrelated 297-case descriptor; a wrong enum/module with the same name/count; initializer requirement substituted for getter; associated RawValue confused with Self; a getter witness loading/transmitting the wrong bits; an unbound generic conformance; changed external binding; one-past-count table entry; out-of-range or nonexecutable target; signed halfword load; changed scale or anchor; and a callback field initialized with a different function after construction. These qualify distinct missing premises rather than mirror a decoder implementation.
